# Extract Design

## When to Use

Use this skill when the user wants to:

- 提取公开网页的视觉风格。
- 把网页设计语言沉淀为可复用参考。
- 获取 typography、color、spacing、surface、component、state、motion、background 和 visual effect 的结构化描述。
- 生成 style guide、style manifest、style specimen 和 starter tokens。

Do not use this skill for:

- 像素级复刻。
- 只截图网页。
- 只下载 CSS 或 DOM。
- 默认采集登录态、后台、账号页或私有文档。
- 多 URL 合成。该能力属于后续版本。

## Output Location

Default output:

```text
<target-project-root>/outputs/extractions/<name>/
```

Rules:

- If the user specifies a target project, use that project as root.
- If the user only provides a URL, use the current working directory as root.
- If the user provides `--out-dir`, use it exactly.
- Do not write new extraction output to this skill's own `assets/theme/` directory.
- `outputs/` is runtime output and should normally be ignored by git.
- Versioned examples belong in `examples/<name>/`.

## Workflow

1. Confirm the target URL is a single public page and choose `<name>`.
2. Create the extraction directory with `guides/`, `evidence/`, `artifacts/`, and `raw/`.
3. Run `scripts/extract-styles.py` to collect computed styles, screenshots, transition scan, library detection, raw data, starter tokens, evidence index, and baseline artifacts.
4. Run `scripts/extract-keyframes.py` when additional motion evidence is visible or suspected.
5. Add or refine `guides/style-guide.md`, `guides/evidence-manifest.md`, and `guides/motion-guide.md` when applicable.
6. Normalize raw findings into `artifacts/style-manifest.json` using `references/schema.md`.
7. Generate or refine `artifacts/style-specimen.html` from the same tokens and manifest.
8. Run `scripts/validate-extraction.py`; use `--strict` before treating the result as complete.

## Output Contract

Every valid extraction must include:

- `guides/style-guide.md`
- `guides/evidence-manifest.md`
- `evidence/evidence-index.json`
- `artifacts/style-manifest.json`
- `artifacts/style-specimen.html`
- `artifacts/tokens.json`
- `artifacts/tokens.css`

When meaningful motion exists, also include:

- `guides/motion-guide.md`
- `raw/keyframes.json` or another motion evidence file

`raw/transition-scan.json` and `raw/library-detect.json` are generated by the baseline extraction. They are evidence files, not proof that a reusable motion pattern exists.

When motion does not exist or cannot be captured:

- Do not generate `guides/motion-guide.md`.
- Record the reason in `guides/evidence-manifest.md`.
- Add a `limitations[]` entry in `artifacts/style-manifest.json`.

## Quality Rules

- Extract the system, not the source page structure.
- Preserve evidence for key conclusions using `ev:<category>/<id>` references.
- Use semantic tokens instead of raw-only names.
- Mark low-confidence or unavailable data explicitly.
- Keep raw measured data in `raw/`; keep reusable conclusions in `artifacts/style-manifest.json`.
- Do not keep `/* REPLACE */` placeholders in generated artifacts.
- Do not treat logos, trademarks, source copy, illustrations, photography, or product IA as reusable design assets.

## Validation

Run:

```bash
python3 scripts/validate-extraction.py outputs/extractions/<name>
python3 scripts/validate-extraction.py --strict outputs/extractions/<name>
```

For repository fixtures:

```bash
python3 scripts/test-validation-fixtures.py
```
